# Tauri 2 官方插件文档格式调研

调研日期：2026-07-30

## 结论

Tauri 2 的“官方插件文档”有两种相关但用途不同的格式：

1. `v2.tauri.app/plugin/*` 的用户指南页是当前最完整、最适合作为本插件主文档基线的格式。
2. `plugins-workspace/plugins/*/README.md` 是仓库和包注册表使用的简版 README 模板，章节更少，通常不展开权限表、错误语义和完整 API。

本插件应以官网指南页的内容顺序为主，同时保留 README 所需的纯 Markdown 写法。不要直接照搬官方 MDX 组件，也不要把社区插件写成 `@tauri-apps/*` 官方包。

## 对照页面

| 插件 | 官网指南 | 官方文档源码 | 重点 |
| --- | --- | --- | --- |
| Dialog | [Dialog](https://v2.tauri.app/plugin/dialog/) | [dialog.mdx](https://github.com/tauri-apps/tauri-docs/blob/v2/src/content/docs/plugin/dialog.mdx) | 标准平台、安装和多场景 Usage；JS、Rust API 分开链接 |
| Clipboard | [Clipboard](https://v2.tauri.app/plugin/clipboard/) | [clipboard.mdx](https://github.com/tauri-apps/tauri-docs/blob/v2/src/content/docs/plugin/clipboard.mdx) | 最小标准页；JS/Rust Tab；默认权限为空并解释安全原因 |
| Shell | [Shell](https://v2.tauri.app/plugin/shell/) | [shell.mdx](https://github.com/tauri-apps/tauri-docs/blob/v2/src/content/docs/plugin/shell.mdx) | 安全敏感插件；在自动权限参考前增加能力文件配置示例 |

三个页面的共同顺序是：

```text
标题、短描述、资源/API 链接
→ Supported Platforms
→ Setup
→ 可选的 Configuration / 迁移说明
→ Usage
→ 可选的 Permissions 说明与 capability 示例
→ Default Permission
→ Permission Table
```

后两个权限章节由官方 [`PluginPermissions`](https://github.com/tauri-apps/tauri-docs/blob/v2/src/components/PluginPermissions.astro) 组件读取插件仓库中的 `permissions/autogenerated/reference.md` 自动渲染，不是在指南中重复手写。

## 官网指南页的固定骨架

### 1. 页面元数据与顶部资源链接

官方 MDX 使用以下 frontmatter：

```yaml
---
title: Dialog
description: Native system dialogs for opening and saving files along with message dialogs.
plugin: dialog
i18nReady: true
---
```

紧接着使用 `PluginLinks`，展示 GitHub、npm 包、crates.io、JavaScript API Reference 和 Rust API Reference。链接的实际生成规则可见官方 [`PluginLinks.astro`](https://github.com/tauri-apps/tauri-docs/blob/v2/src/components/PluginLinks.astro)。

对普通 README 的等价写法应是：

- 一个清晰的 H1；
- 一句话说明插件解决的问题；
- 只放真实可访问的 GitHub、npm、crates.io、JavaScript API 和 Rust API 链接；
- 未发布的包或尚未生成的 API 文档不应放占位链接。

本项目的实际包名是：

- Rust crate：`tauri-plugin-screenshot`
- JavaScript package：`tauri-plugin-screenshot-api`

不能为了模仿官方格式，将 JavaScript 包写成并不存在的 `@tauri-apps/plugin-screenshot`。
Tauri 的官方插件开发指南也明确区分官方与第三方命名空间，第三方 JavaScript 包推荐使用自己的 scope。来源：[Plugin Development — Naming Convention](https://v2.tauri.app/develop/plugins/#naming-convention)。

### 2. Supported Platforms

三个官方页面都先给 `## Supported Platforms`。官方 [`Compatibility.astro`](https://github.com/tauri-apps/tauri-docs/blob/v2/src/components/plugins/Compatibility.astro) 会先显示最低 Rust 版本，再输出三列表格：

| Platform | Level | Notes |
| --- | --- | --- |
| 平台名 | 支持等级图标 | 限制或平台差异 |

参考页面：

- [Dialog Supported Platforms](https://v2.tauri.app/plugin/dialog/#supported-platforms)
- [Clipboard Supported Platforms](https://v2.tauri.app/plugin/clipboard/#supported-platforms)
- [Shell Supported Platforms](https://v2.tauri.app/plugin/shell/#supported-platforms)

本插件的 README 应在这里明确：

- Rust 1.77.2+；
- macOS 15.2+；
- Windows 10/11；
- Linux、Android、iOS 当前不支持；
- 不要只写实现技术名，应优先说明用户可感知的支持级别与限制。

如果未来要接入 Tauri 官网的自动兼容性表，还应在 `Cargo.toml` 的 `[package.metadata.platforms.support]` 中把 Windows、macOS 标为 `full`，其余平台标为 `none`。官方表格数据由构建器读取这些元数据生成：

- [Compatibility table build script](https://github.com/tauri-apps/tauri-docs/blob/v2/packages/compatibility-table/build.ts)
- [Clipboard Cargo platform metadata](https://github.com/tauri-apps/plugins-workspace/blob/v2/plugins/clipboard-manager/Cargo.toml)
- [Autostart desktop platform metadata](https://github.com/tauri-apps/plugins-workspace/blob/v2/plugins/autostart/Cargo.toml)

### 3. Setup：Automatic 与 Manual

官方页面将 Setup 分为两个 Tab。

Automatic 使用各包管理器调用 Tauri CLI：

```sh
npm run tauri add dialog
yarn run tauri add dialog
pnpm tauri add dialog
deno task tauri add dialog
bun tauri add dialog
cargo tauri add dialog
```

Manual 固定为三步：

1. 在 `src-tauri` 中安装 Rust crate；
2. 在 `src-tauri/src/lib.rs` 中注册插件；
3. 如果要从前端调用，再安装 JavaScript guest bindings。

官方初始化示例采用 Tauri 2 的 `lib.rs` 结构：

```rust
#[cfg_attr(mobile, tauri::mobile_entry_point)]
pub fn run() {
    tauri::Builder::default()
        .plugin(tauri_plugin_dialog::init())
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}
```

精确格式可对照：

- [Dialog Setup](https://v2.tauri.app/plugin/dialog/#setup)
- [Clipboard Setup](https://v2.tauri.app/plugin/clipboard/#setup)
- [Shell Setup](https://v2.tauri.app/plugin/shell/#setup)

应用到本插件时需要注意：

- 只有在 `tauri add screenshot` 已经真实可用并验证过时，才写 Automatic 安装；否则只保留 Manual，不能复制一个会失败的官方命令。
- Manual 应列出 npm、yarn、pnpm、deno、bun 的实际安装命令，包名保持 `tauri-plugin-screenshot-api`。
- capability 配置不能遗漏。Tauri 官方权限文档说明，CLI 添加插件时会特殊处理默认权限；手动安装的社区插件应明确告诉用户需要把权限加入 capability。来源：[Permissions — Configuration Files](https://v2.tauri.app/security/permissions/#configuration-files)。

对仅支持桌面的插件，官方还会使用 target-specific Cargo 依赖并在初始化处加 `#[cfg(desktop)]`。可参考 [Autostart Setup](https://v2.tauri.app/plugin/autostart/#setup) 及其 [MDX 源码](https://github.com/tauri-apps/tauri-docs/blob/v2/src/content/docs/plugin/autostart.mdx)。本插件只支持 Windows/macOS时，可以采用同一表达方式，避免让移动端用户误以为安装后可工作。

### 4. Configuration 与操作系统权限

Configuration 不是每个插件都有，但涉及平台清单、隐私说明或系统授权时会放在 Setup 与 Usage 之间。

Geolocation 的官方页面就是这种写法：先给 iOS `Info.plist` 隐私描述，再说明 Android manifest 权限，最后进入 Usage。参考：

- [Geolocation 文档](https://v2.tauri.app/plugin/geolocation/)
- [geolocation.mdx 源码](https://github.com/tauri-apps/tauri-docs/blob/v2/src/content/docs/plugin/geolocation.mdx)

因此截图插件应新增独立的“平台配置”或“系统权限”小节，而不应把所有内容埋在交互列表中：

- macOS 首次截图会触发“屏幕录制”系统授权；
- 用户拒绝时返回 `permissionDenied`；
- 系统要求时需要退出并重新启动应用；
- Windows 当前不需要额外的系统授权流程。

这里必须区分两类权限：

- 操作系统隐私权限：macOS 屏幕录制授权；
- Tauri ACL 权限：`screenshot:*` capability 标识。

两者不能合并成同一个“权限已开启”的模糊描述。

### 5. Usage

官方插件会先用一句话说明 API 可用于 JavaScript、Rust，或只支持其中一种，再给最小可运行示例：

- Clipboard 和 Shell 使用同步的 JavaScript / Rust Tabs；
- Dialog 因场景较多，分别建立 `### JavaScript` 和 `### Rust`，再按行为拆分小节。

来源：

- [Clipboard Usage](https://v2.tauri.app/plugin/clipboard/#usage)
- [Shell Usage](https://v2.tauri.app/plugin/shell/#usage)
- [Dialog Usage](https://v2.tauri.app/plugin/dialog/#usage)

截图插件的 Usage 建议至少覆盖：

1. JavaScript 最小调用；
2. `captured` 与 `cancelled` 两个正常结果分支；
3. 将 `Uint8Array` 转成 `Blob` 的预览示例；
4. `CaptureOptions` 的默认值与单位；
5. 如果正式支持 Rust 侧直接调用，再给 `ScreenshotExt` 示例；否则不要笼统声称“两端都可用”。

交互说明、多显示器坐标和放大镜行为属于本插件的重要产品语义，可以放在 Usage 后作为独立章节，但不应代替最小 API 示例。

### 6. Permissions

官方插件文档在页面末尾呈现两层内容。

第一层是可选的手写 `## Permissions`：

- 用于解释为什么默认能力不够；
- 给出 `src-tauri/capabilities/*.json` 的最小配置；
- 对 scope 敏感的命令展示 allow/deny 范围。

Shell 使用了这个模式，因为执行程序属于高风险操作。来源：[Shell Permissions](https://v2.tauri.app/plugin/shell/#permissions)。

第二层是自动生成的：

```text
## Default Permission
默认权限的安全含义
#### Granted Permissions
#### This default permission set includes the following
## Permission Table
每一个 allow-* / deny-* 标识及说明
```

三种默认权限策略的官方实例：

- Dialog 默认开放对话框命令：[default.toml](https://github.com/tauri-apps/plugins-workspace/blob/v2/plugins/dialog/permissions/default.toml) 与 [生成的 reference.md](https://github.com/tauri-apps/plugins-workspace/blob/v2/plugins/dialog/permissions/autogenerated/reference.md)。
- Clipboard 认为读写剪贴板具有固有风险，因此默认权限为空：[default.toml](https://github.com/tauri-apps/plugins-workspace/blob/v2/plugins/clipboard-manager/permissions/default.toml) 与 [生成的 reference.md](https://github.com/tauri-apps/plugins-workspace/blob/v2/plugins/clipboard-manager/permissions/autogenerated/reference.md)。
- Shell 默认只开放有限的 `open`，执行命令需要显式 scope：[default.toml](https://github.com/tauri-apps/plugins-workspace/blob/v2/plugins/shell/permissions/default.toml) 与 [生成的 reference.md](https://github.com/tauri-apps/plugins-workspace/blob/v2/plugins/shell/permissions/autogenerated/reference.md)。

截图插件已有 `permissions/autogenerated/reference.md`，README 应据此完整展示：

- `screenshot:default`；
- 默认包含 `allow-capture-area`、`allow-take-capture`；
- `allow-*` 与 `deny-*` 的完整表；
- 最小 capability JSON。

不要只给 `"screenshot:default"` 而不解释它实际上授权了什么。

Tauri 对权限标识、默认权限和配置文件的权威说明：

- [Permissions](https://v2.tauri.app/security/permissions/)
- [Capabilities](https://v2.tauri.app/security/capabilities/)
- [Using Plugin Permissions](https://v2.tauri.app/learn/security/using-plugin-permissions/)

### 7. API Reference

官方指南不会在正文重复完整 API，而是在顶部链接两套生成文档：

- JavaScript API：由 `guest-js` 中的 TypeScript 类型与 TSDoc 生成；
- Rust API：由 crate 的 rustdoc 发布到 docs.rs。

Tauri 文档仓库中的实际生成流程使用 TypeDoc 与 Markdown 插件，来源：[JavaScript API generator](https://github.com/tauri-apps/tauri-docs/blob/v2/packages/js-api-generator/build.ts)。

Clipboard JavaScript API 的实际条目格式是：

```text
函数名与完整签名
→ 描述
→ Platform-specific（如有）
→ Parameters（如有）
→ Returns
→ Example
→ Since
→ Source
```

可直接对照：

- [Clipboard JavaScript API Reference](https://v2.tauri.app/reference/javascript/clipboard-manager/)
- [clipboard guest-js 源码](https://github.com/tauri-apps/plugins-workspace/blob/v2/plugins/clipboard-manager/guest-js/index.ts)
- [Dialog JavaScript API Reference](https://v2.tauri.app/reference/javascript/dialog/)
- [Dialog Rust API Reference](https://docs.rs/tauri-plugin-dialog/latest/tauri_plugin_dialog/)

截图插件若要达到相同质量，应给 `guest-js/index.ts` 的模块、导出类型和 `captureArea` 补齐：

- 一句话描述；
- `@example`；
- `@returns`；
- `@since`；
- 平台差异；
- Promise rejection 的结构化错误类型。

在 JS 与 Rust API 尚未发布前，README 可以暂时内联一张 API 表，但不能放无效的 “API Reference” 链接。

### 8. 错误与安全说明

对照的三个标准指南页都没有固定的 `## Errors` 章节。官方更常见的处理方式是：

- 可恢复的正常分支直接写进 Usage 示例；
- 平台差异使用 note/caution；
- 参数、返回值和失败语义写进生成的 API Reference；
- 高风险能力单独写 Permissions、Security 或顶部 caution。

第一方实例：

- Localhost 在简介后立刻给安全 caution：[Localhost](https://v2.tauri.app/plugin/localhost/) 与 [localhost.mdx](https://github.com/tauri-apps/tauri-docs/blob/v2/src/content/docs/plugin/localhost.mdx)。
- File System 有独立 `## Security`，解释路径遍历和 scope：[File System Security](https://v2.tauri.app/plugin/file-system/#security) 与 [file-system.mdx](https://github.com/tauri-apps/tauri-docs/blob/v2/src/content/docs/plugin/file-system.mdx)。
- Shell 把危险命令的约束放在 `## Permissions` 和 capability scope 示例中：[Shell Permissions](https://v2.tauri.app/plugin/shell/#permissions)。
- Shell 的 guest bindings 直接在 API 注释中说明权限拒绝会造成 Promise rejection：[shell/guest-js/index.ts](https://github.com/tauri-apps/plugins-workspace/blob/v2/plugins/shell/guest-js/index.ts)。

本插件返回结构化错误，单独增加 `## Error Handling` 是合理的项目特化，不会破坏官方风格。建议使用表格而不是只贴 TypeScript union：

| 字段 | 需要说明 |
| --- | --- |
| `code` | 每个稳定错误码及触发条件 |
| `message` | 供诊断展示，不建议业务逻辑依赖其文本 |
| `recoverable` | 用户是否可在当前运行中重试 |

同时明确：

- 用户取消返回 `{ status: "cancelled" }`，不是异常；
- 同时只能存在一个会话，冲突返回 `busy`；
- macOS 拒绝屏幕录制授权返回 `permissionDenied`；
- 截图数据可能包含敏感信息，业务端不应默认上传、记录或长期保留；
- `take_capture` 返回的 PNG 是一次性读取结果，重复读取会得到 `resultUnavailable`。

## 官方仓库 README 的简版模板

官网指南页之外，官方插件仓库自身 README 采用另一套固定顺序：

```text
Banner
→ 一句话说明
→ Platform / Supported 表
→ Install
   → Rust 最低版本
   → crates.io / Git / submodule 三种来源说明
   → Cargo.toml
   → JavaScript guest bindings
→ Usage
   → 注册插件
   → JavaScript 示例
→ Contributing
→ Partners
→ License
```

对照源码：

- [Dialog README](https://github.com/tauri-apps/plugins-workspace/blob/v2/plugins/dialog/README.md)
- [Clipboard README](https://github.com/tauri-apps/plugins-workspace/blob/v2/plugins/clipboard-manager/README.md)
- [Shell README](https://github.com/tauri-apps/plugins-workspace/blob/v2/plugins/shell/README.md)

这些 README 比官网指南页简略，有的示例甚至留空，因此不应把它当作完整用户文档的唯一基准。本项目可以采用其顶部、安装和 License 结构，但权限、平台授权、错误和坐标语义应按官网指南页补齐。

## 建议给截图插件采用的最终目录

```text
# Tauri Plugin Screenshot

## Supported Platforms
最低 Rust 版本 + Platform / Level / Notes

## Setup
### Automatic（仅在验证可用后）
### Manual
Rust crate → init() → JS package → capability

## Platform Configuration
### macOS
### Windows

## Usage
### JavaScript
### Rust（确实需要公开时）

## Interaction
框选、窗口吸附、二次确认、放大镜、取消/确认快捷操作

## Capture Result and Coordinates
返回类型、物理/逻辑像素、多屏原点

## API Reference

## License
```

## 落地时的核对清单

- [ ] 包名、插件标识和 capability 标识三者没有混用。
- [ ] 没有虚构 `@tauri-apps/*`、`tauri add` 或尚未发布的链接。
- [ ] 安装示例使用 `src-tauri/src/lib.rs` 和 Tauri 2 初始化方式。
- [ ] JS 示例同时处理 `captured` 和 `cancelled`。
- [ ] 平台表写清 macOS 15.2+ 与 Windows 10/11。
- [ ] macOS 系统授权与 Tauri ACL 分开解释。
- [ ] 默认权限列出实际包含的两个命令。
- [ ] Permission Table 与 `permissions/autogenerated/reference.md` 一致。
- [ ] 错误码表与 `src/error.rs` 一致。
- [ ] 坐标单位、选区最小尺寸单位和多屏原点有明确说明。
- [ ] API Reference 链接真实存在；否则以内联 API 表替代。
